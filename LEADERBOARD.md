## The benchmarks

## Ranking

An entry is one system and configuration. Ranked by its **held-out mean**: the mean of its accuracies over the benchmarks it was run on, leaving out its home turf (†) — a tool is not credited for recognising its own training files. Entries run on fewer than 6 benchmarks, or only on their home turf, are listed after the ranking. *Mean, all run* includes the home turf; *right, all cases* pools the cases of every benchmark run (dominated by the largest). *n/a*: the tool answers from the file name only and the benchmark has no file names; *—*: not run.

**How to read.** Every entry answers, for each file, the language it is written in. A case is right when the answer is exactly one language and an accepted one; *no answer / undecided* means the entry abstained or returned several candidates; `Text` means it called a source file plain text. Each benchmark's README says where its labels come from (bench-cobol: an LLM judge (Claude Sonnet 4.6), else the study's rules; bench-fsf: an LLM judge (Claude Sonnet 4.6), the study's rule agrees on all; bench-hello: the contributor (the language the file is named after); bench-hljs: highlight.js' maintainers (the test's directory, a language id), crosswalked to Linguist's names; bench-linguist: Linguist's maintainers (the sample's directory); bench-m: blind human review; two LLM judges agree on all; bench-pygments: Pygments' maintainers (the example's directory, a lexer alias), crosswalked to Linguist's names; bench-rosetta: the contributor (the solution's language heading on rosettacode.org); bench-rouge: Rouge's maintainers (the file is named after its lexer's tag), crosswalked to Linguist's names; bench-rpgle: an LLM judge (Claude Sonnet 4.6), the study's rules beside it; bench-smola: a human for 1,107 files (gold); for 2,765, the dataset's vote, i.e. Linguist's own answer of 2019–2022 (silver)). **Kinds:** *Synid* — a version of Synid, the CodeCommons syntax-identification tool, in its default configuration or with one strategy turned off (a setting of Synid's configuration file); *other identifier* — another tool, as a reference point; *specialised rules* — rules written for one benchmark's problem only, a ceiling for what targeted rules achieve rather than a general identifier; *lightweight LLM* — a small, cheap model asked the language (not used to build the ground truth); *candidates + lightweight LLM* — the languages PL-ultimate-llm associates with the file's extension, among which the model chooses (a broad list when none fits).
