# Leaderboard — bench-fsf

Generated by `python3 tools/leaderboard.py` · benchmark `bench-fsf/1`, 467 cases ([README](README.md)). Ranked by accuracy, then precision of language answers. Tag columns: right / cases carrying that tag, over all tiers (see the README); *weighted to the population* re-weights the stratified draw to the population it was drawn from.

**What it is.** archived .fsf files: FSL FEAT designs (Tcl), git-annex pointers, XML and a shader — 467 cases (whole file), 6 languages · labels: an LLM judge (Claude Sonnet 4.6), the study's rule agrees on all · file names: real · sampling: population-sampled with weights (uniform by-file sample; FEAT designs drawn down to 300) · source: Software Heritage, via PL-ultimate-llm's .fsf study (swh-evidence-v1@274fa4cc8). **Strengths.** drawn uniformly from the archive's 21,802 .fsf files, with population weights; an extension no language claims: configuration in Tcl syntax, pointers that are not code; real file names and repositories (qualified SWHIDs). **Weaknesses.** labels by one LLM judge; no human check; Tcl for a FEAT design is a choice (its syntax); the judge calls it not a programming language; 300 FEAT designs are near-duplicates generated by a GUI; the cascade's candidates and the rule were built from these files.

**How to read.** Every entry answers, for each file, the language it is written in. A case is right when the answer is exactly one language and an accepted one; *no answer / undecided* means the entry abstained or returned several candidates; `Text` means it called a source file plain text. Each benchmark's README says where its labels come from (bench-fsf: an LLM judge (Claude Sonnet 4.6), the study's rule agrees on all). **Kinds:** *Synid* — a version of Synid, the CodeCommons syntax-identification tool, in its default configuration or with one strategy turned off (a setting of Synid's configuration file); *other identifier* — another tool, as a reference point; *specialised rules* — rules written for one benchmark's problem only, a ceiling for what targeted rules achieve rather than a general identifier; *lightweight LLM* — a small, cheap model asked the language (not used to build the ground truth); *candidates + lightweight LLM* — the languages PL-ultimate-llm associates with the file's extension, among which the model chooses (a broad list when none fits).
