# bench-cobol — archived `.cbl` / `.CBL` files, drawn from the archive with weights

Part of [synid-bench](../../README.md). **605 `.cbl` and `.CBL` files archived by
[Software Heritage](https://www.softwareheritage.org)**, drawn uniformly from the
276,831 contents with these extensions, with real file names, origins and
population weights. Labels come from an LLM judge or, where the judge did not
look, from the study's rules (**silver**): no human checked them. The cases come
from the COBOL extension study of
[PL-ultimate-llm](https://github.com/acherm/PL-ultimate-llm) (branch
`swh-evidence-v1`, commit `274fa4cc8`, `docs/cobol_swh_study.md`).

COBOL in the archive is not COBOL in textbooks: programs of a Japanese medical
billing system with Shift-JIS comments, copybooks with no division at all, code
generated by IDEs, both casings of the extension — and contamination: 41 % of
the files are `WBC_*_FOO.CBL` stubs ("This is cobol file number N") from one
synthetic repository, and Calibre comic-book reading lists squat on `.cbl`. The
benchmark asks whether an identifier recognises COBOL from its content, and
whether it trusts the extension on files that are not COBOL.

## Where the files and labels come from

- **Population and sample.** The study's population tables list the 276,831
  unique `.cbl`/`.CBL` contents of the archive and their origins
  (graph-derived). Its experiment E3 is a uniform random sample of 1,000 of them,
  fetched from Software Heritage by sha1_git.
- **Labels.** Claude Sonnet 4.6 (OpenRouter, temperature 0, structured output,
  schema `cobol-judge/2`: is it COBOL, and if not what; dialect, program type…)
  judged the files with at least two COBOL divisions — a cost gate — after seeing
  the bytes, the file name and the study's indicators: 526 of the 1,000. Seven
  gate-skipped files were re-judged later, when a second labeller flagged them
  (`data/derived/jev/cobol/gate_rescue.jsonl`, local data of PL-ultimate-llm,
  read when present): copybooks and fragments, all COBOL (tag `gate-rescued`;
  the rules said `other`, tag `judge-rules-disagree`). The other files carry the
  label of the study's content rules (`tools/cobol/reclassify.py`, tag
  `rules-only`): COBOL programs, copybooks and generated code (18), ReadingList
  XML (15), and the synthetic stubs, which a human assertion over their
  repository also labels not COBOL (`reviews_cobol/_rules.jsonl`, tag
  `human-origin-rule`). One file in the archive has a human review; it is not in
  the sample, so every case is silver.
- **A copybook is COBOL.** A copybook is COBOL source text brought in by `COPY`
  (data descriptions, constants); Linguist files `.cpy` under COBOL. Expected
  `COBOL`, tag `copybook` (15).
- **Drawn down.** The 408 stubs of the sample are near-identical one-liners; a
  seeded draw keeps 40 (seed 2026), weighted back to their share.
- **Left out** of the 1,000: 21 text files the rules call `other` (no label:
  Crucible S-expressions, FrontPage metadata, JCL, a note in French…), 5 binary
  files (3 binary data, 2 CCBridge comic libraries), 1 low-confidence verdict.
  They are 2.7 % of the population, and they are the most varied part of it: a
  human review of them would be the first addition.
- **Weights.** `weight` = the stratum's share of the uniform sample × 276,831 /
  the number of cases in the stratum; strata are label × source of the label:
  COBOL (judge) 532 cases, COBOL (rules) 18, XML (rules) 15 — 276.8 each —, Text
  (origin rule) 40 — 2,823.7 each.
- **Names.** `filename` is the archived file name, with the extension's case
  (`ext` `.CBL` for 316 cases, `.cbl` for 289). Three names contain the label
  (`SaludoCobol.cbl`, `Cobol005.cbl`, `cobolGreeting.cbl`): they are run as
  `source.cbl` (tag `renamed`, original in `path`). `qualified_swhid` carries the
  origin and the path from the study's origin tables; the path is omitted in 12
  cases where the table's path names another file, the origin in 2 with no row.
  The contents are archived (fetched by the study from Software Heritage;
  spot-checked with the public API on 2026-10-03).
- **Files are not stored** in this repository (53.6 MB; 75 files over 200 KB,
  the largest 1.6 MB): `build_cases.py` writes `files/<sha1_git>` from
  PL-ultimate-llm's cache, else from the Software Heritage API
  (`$SWH_TOKEN` optional; anonymous access is rate-limited), each checked against
  its sha1_git. `files/` must not be committed.

## Strengths and weaknesses

- **Strengths.** Drawn uniformly from the archive, with weights: the weighted
  score is an estimate for `.cbl`/`.CBL` files as archived, contamination
  included. Real COBOL from many dialects and eras, with real names, both
  casings and non-UTF-8 bytes. Copybooks, which have none of the divisions
  identifiers look for.
- **Weaknesses.** Labels by one LLM judge, which saw the rules' indicators, or by
  the rules alone (73 cases); nobody checked them, and LLM labels may favour LLM
  entries. The judge saw only files with two divisions: the judged COBOL is
  the easy COBOL. The files the rules could not name are left out. With the file
  name, an identifier that trusts the extension is right on all COBOL (91 %
  unweighted) and wrong on every stub — which carry 42 % of the weight.
- **Home turf.** The rules were bootstrapped from the judge's labels on the
  study's files and are the only reference of the rules-only cases;
  PL-ultimate-llm's candidates for the Jev cascade include what the study
  observed (here COBOL, also Linguist's claim). See `contamination.json`.

## Build and run

```bash
python3 benchmarks/bench-cobol/build_cases.py            # needs PL-ultimate-llm at 274fa4cc8 ($PL_ULTIMATE_LLM)
python3 benchmarks/bench-cobol/export_reference_runs.py  # the study's rules and Jev's stored decisions (no API call)
python3 tools/run.py benchmarks/bench-cobol --synid path/to/synid --label mytest
SYNID=path/to/synid benchmarks/bench-cobol/reproduce.sh   # everything
```

`build_cases.py` reads the study's reports, rule labels, worklist and origin
tables from PL-ultimate-llm's git at commit `274fa4cc8` (shared code:
`tools/study_cases.py`); a rerun gives the same `cases.csv`. All cases are
silver: `tools/score.py` prints the weighted accuracy for gold only; the
leaderboard weights every benchmark that has weights.

- **With the file name, the extension decides.** Every identifier that maps `.cbl` and `.CBL` to
  COBOL — Synid `48c3c45` and `9bc1c32` (with any one strategy off too), GitHub Linguist 7–9,
  go-enry, linguist-js, Hyperpolyglot, Pygments 2.14–2.21, Rouge, cloc, scc, tokei, ctags —
  answers COBOL on all 605 files: right on the 550 COBOL files (copybooks, Shift-JIS comments and
  the 7 files the rules missed included), wrong on the 40 stubs and the 15 reading lists. Unweighted
  that is 90.9 %; weighted, 56.5 %, because the stubs are 41 % of the archive's `.cbl`/`.CBL`
  files (42 % of the benchmark's weight, once the files left out are set aside).
- **Neovim knows `.cbl` but not `.CBL`**: COBOL on the 274 lower-case COBOL files, no answer on
  every `.CBL` file (tag `upper-case-ext`). Chroma's file patterns do not include `.cbl`: its
  content analysis names Zed (207) or GDScript (83). ohcount and gengo have no COBOL.
- **From the content alone**, Synid `48c3c45` never says COBOL: no answer on 273 COBOL files,
  ALGOL 68 on 118, `Text` on 99, Vim script on 45 — it is right only on the 40 stubs (`Text`), which
  the weights turn into 41.9 %. Linguist and go-enry without the name answer only on the reading
  lists (XML); Pygments' content guess names GoogleSQL (342). The neural guessers do better:
  Guesslang 506 of the 550 COBOL files (all 15 copybooks; but INI on 35 stubs),
  vscode-languagedetection 365, Magika 1.0.3 282 (`Text` on 177, Fortran on 78) — and Magika is
  right on every stub and reading list, which makes it the best weighted score of the
  identifiers that do not read the study (72.5 %). Magika 0.5.1 and libmagic say `Text` on almost
  all COBOL.
- Jev with the study's labels says COBOL on 549 of the 550 COBOL files, but also on 34 of the 40
  stubs (37 with the file name): "This is cobol file number N" lures it. The study's rules, built
  from the judge's labels and the reference of the rules-only cases, get 598/605.

Not run here: hf-codeberta, hf-framebyframe, hf-philomath and plangrec (slow transformer or memory-heavy tools, left to a later throttled batch; highlight.js too, which did not finish on these 54 MB).
