# Leaderboard — bench-rosetta

Generated by `python3 tools/leaderboard.py` · benchmark `bench-rosetta/1`, 1589 cases ([README](README.md) · [history of Synid versions](HISTORY.md)). Ranked by accuracy, then precision of language answers. Tag columns: right / cases carrying that tag, over all tiers (see the README).

**What it is.** Rosetta Code solutions, up to 2 per language, 848 languages — 1589 cases (snippet), 835 languages · labels: the contributor (the solution's language heading on rosettacode.org) · file names: label-derived · sampling: random per language (seed 20261003): up to 2 solutions of 2 tasks, among files of 3+ non-blank lines and at most 100 KB · source: https://github.com/acmeism/RosettaCodeData@1d47586. **Strengths.** the widest coverage: 848 Rosetta Code languages, the tail included (the median language has 18 solutions in the dump); labels declared by the authors, produced by no identifier; the same tasks across languages: the language differs, not the topic; two thirds of the cases in languages Linguist does not know: an honest measure of coverage. **Weaknesses.** file names derived from the label through acmeism's extension table (often invented): with names, a tool reads the label back; the content-only runs are the fair reading; wiki code blocks, often short (202 cases of 3-4 non-blank lines), not files of projects; fine-grained categories: dialects and implementations (BBC BASIC, Free Pascal) are languages of their own, not mapped to Linguist's broader names; Rosetta Code is training data of some classifiers and, most likely, of every large language model.

**How to read.** Every entry answers, for each file, the language it is written in. A case is right when the answer is exactly one language and an accepted one; *no answer / undecided* means the entry abstained or returned several candidates; `Text` means it called a source file plain text. Each benchmark's README says where its labels come from (bench-rosetta: the contributor (the solution's language heading on rosettacode.org)). **Kinds:** *Synid* — a version of Synid, the CodeCommons syntax-identification tool, in its default configuration or with one strategy turned off (a setting of Synid's configuration file); *other identifier* — another tool, as a reference point; *specialised rules* — rules written for one benchmark's problem only, a ceiling for what targeted rules achieve rather than a general identifier; *lightweight LLM* — a small, cheap model asked the language (not used to build the ground truth); *candidates + lightweight LLM* — the languages PL-ultimate-llm associates with the file's extension, among which the model chooses (a broad list when none fits).
