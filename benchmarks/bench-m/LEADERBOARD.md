# Leaderboard — bench-m

Generated by `python3 tools/leaderboard.py` · benchmark `bench-m/1`, 54 cases ([README](README.md) · [history of Synid versions](HISTORY.md)). Ranked by accuracy, then precision of language answers. Tag columns: right / cases carrying that tag, over all tiers (see the README); *weighted to the population* re-weights the stratified draw to the population it was drawn from.

**What it is.** archived .m files: Objective-C, MATLAB/Octave, Wolfram, Mercury, MUMPS, Magma… — 54 cases (whole file), 8 languages · labels: blind human review; two LLM judges agree on all · file names: real · sampling: population-sampled with weights (stratified, hard cases over-sampled) · source: Software Heritage, via PL-ultimate-llm's .m study (swh-evidence-v1). **Strengths.** labels checked by a human, blind; drawn from the archive, with population weights; one hard ambiguous extension, in depth; small: every failure can be read. **Weaknesses.** 54 files, 8 languages, one extension: wide intervals; MATLAB is 32 of 54; the cascade's candidates include what the .m study observed in these files.

**How to read.** Every entry answers, for each file, the language it is written in. A case is right when the answer is exactly one language and an accepted one; *no answer / undecided* means the entry abstained or returned several candidates; `Text` means it called a source file plain text. Each benchmark's README says where its labels come from (bench-m: blind human review; two LLM judges agree on all). **Kinds:** *Synid* — a version of Synid, the CodeCommons syntax-identification tool, in its default configuration or with one strategy turned off (a setting of Synid's configuration file); *other identifier* — another tool, as a reference point; *specialised rules* — rules written for one benchmark's problem only, a ceiling for what targeted rules achieve rather than a general identifier; *lightweight LLM* — a small, cheap model asked the language (not used to build the ground truth); *candidates + lightweight LLM* — the languages PL-ultimate-llm associates with the file's extension, among which the model chooses (a broad list when none fits).
